## Как использовать с агентом

**Не отдавать всё сразу.** Контекстное окно уйдёт на бизнес-историю, а не на код.

Рабочая последовательность:

1. `CLAUDE.md` подхватывается агентом сам и ведёт к остальному
2. `04-agent-brief.md` целиком — конституция на проекте
3. `05-state.md` и `06-decisions.md` целиком — где мы и что уже решено. Без них агент переоткрывает закрытые вопросы
4. Плюс `03-tech-spec.md` целиком — архитектура и модель данных нужны всегда
5. Плюс **только тот раздел** `02-requirements.md`, который относится к текущей задаче
6. `01-context.md` — только если агент задаёт вопрос «почему так решили»

**Обратный ход обязателен.** Агент, закончивший задачу, обновляет `05-state.md` и при необходимости `06-decisions.md`. Правила — в `CLAUDE.md`.

## Статус проекта

**Стадия:** концепция подтверждена частично, идёт сбор данных с рынка.

> Текущее состояние, следующий шаг и открытые вопросы — в `05-state.md`. Этот раздел описывает только рыночную стадию.

**Что подтверждено:**

- Интерфейс конкурента изучен по видеозаписи демонстрации
- Формула рейтинга конкурента изучена по первоисточнику (ADR-002)
- Экономика турнира собрана со слов действующего организатора
- Присутствие конкурента в Казахстане подтверждено

**Что не подтверждено и блокирует старт разработки:**

- Готовность игроков потерять накопленный рейтинг конкурента
- Точная модель оплаты, которую применяет конкурент в Казахстане
- Готовность клубов проводить больше мелких турниров при снижении порога

> ⚠️ До закрытия этих трёх вопросов писать продакшн-код преждевременно. Допустимо: прототип модуля проведения турнира для проверки скорости ввода счёта.
>
> **Исключение — чистые пакеты `rating` и `brackets`.** От рыночных гипотез они не зависят: формула рейтинга и генерация сеток нужны при любом исходе, переписывать их не придётся. Обоснование — `05-state.md`, раздел 7.

## Словарь терминов

| Термин                  | Значение                                                     |
| ----------------------- | ------------------------------------------------------------ |
| **Организатор**         | Клуб или тренер, проводящий турнир. Основной платящий клиент |
| **Участник**            | Игрок, зарегистрированный на конкретный турнир               |
| **Встреча (матч)**      | Одна игра между двумя участниками до N выигранных сетов      |
| **Сет**                 | Партия до 11 очков с разницей в 2                            |
| **Схема**               | Формат проведения: круговая, сетка, группы + плей-офф        |
| **Этап**                | Логическая часть турнира: групповой этап, финал              |
| **Планка**              | Верхняя граница рейтинга для допуска к турниру               |
| **Рейтинговая встреча** | Матч, результат которого влияет на рейтинг                   |
| **Вне зачёта**          | Участник играет, но его результаты не идут в рейтинг         |
| **Провизорный рейтинг** | Рейтинг игрока, сыгравшего менее 20 рейтинговых встреч       |
