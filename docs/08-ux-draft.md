# 08. UX-черновик: маршруты и экраны

_Карта маршрутов и разбор ключевых экранов._

> **Это черновик, а не обязательство.** Разделы 2, 3 и 6 описывают то, чего в коде нет, и заводятся в работу только через `05-state.md` и решение владельца продукта. Три рыночные гипотезы не закрыты (`00-README.md`), и продуктовая спецификация вперёд них — предположение.
>
> **Обязательны к исполнению разделы 1, 4 и 5:** это уже написанные части продукта и требования к консоли судьи, идущие из ТЗ.
>
> Визуальный язык, токены и общие паттерны — `07-design-system.md`. Здесь только маршруты и экраны.

## 1. Что есть в коде сегодня

Факт, снятый с `kttf-front/src/routes`. Публичная часть и кабинет — одна оболочка с общей шапкой (ADR-043), консоль — своя. Плюс экран зала без оболочки.

```
/                                    Публичная главная
/tournaments                         Календарь турниров
/tournaments/:tournamentId           Турнир: условия, состав, сетка, результаты
/ratings                             Рейтинг страны
/players/:playerId                   Профиль игрока
/clubs                               Клубы: поиск по названию, выбор города
/clubs/:clubId                       Клуб: контакты, турниры, игроки, организаторы
/login                               Вход
/sign-up                             Регистрация

/cabinet                             Кабинет
/cabinet/clubs                       Мои клубы
/cabinet/clubs/new                   Новый клуб
/cabinet/club/:clubId                Управление: турниры по стадиям, данные, состав
/tournaments/new                     Создание турнира, ?club= выбирает клуб

/console                             Выбор турнира для проведения
/console/:tournamentId               Проведение турнира

/screen/:publicToken                 Экран зала, без авторизации
```

**Вход — логин или телефон плюс пароль** (ТЗ 2.1, ADR-034). Одноразовых кодов по SMS в продукте нет: подтверждать владение номером нечем. Формулировка «вход по телефону» в любых макетах ошибочна — поле одно, человек вводит то, что помнит.

## 2. Куда карта растёт — черновик

Ни один маршрут ниже не заведён. Имена согласованы с существующими: кабинет живёт на `/cabinet`, а не на `/me` или `/club/:id`, — второй корень для той же роли создаст две навигации там, где нужна одна.

### 2.1. Публичная часть и игрок

```
/tournaments/:id?tab=overview|players|draw|results   вкладки страницы турнира
/players/:id/matches                 История матчей
/players/:id/vs/:opponentId          Личные встречи
/clubs                               Клубы
/clubs/:id                           Клуб: расписание, турниры, состав
```

Вкладки турнира — search params TanStack Router, а не отдельные маршруты: состояние вкладки обязано попадать в ссылку (`07-design-system.md`, 6.2).

### 2.2. Кабинет

```
/cabinet                             Сводка по роли
/cabinet/tournaments                 Мои турниры или турниры клуба
/cabinet/matches                     Мои матчи
/cabinet/settings                    Язык, уведомления, приватность
/cabinet/club/:clubId                Клуб: сводка
/cabinet/club/:clubId/tournaments/:id/edit      Настройки турнира
/cabinet/club/:clubId/tournaments/:id/players   Состав, ручное добавление
/cabinet/club/:clubId/tournaments/:id/draw      Жеребьёвка и расстановка
/cabinet/club/:clubId/members        Организаторы и судьи
/cabinet/club/:clubId/billing        Баланс, списания, документы
/cabinet/club/:clubId/settings       Данные клуба, зал, столы
```

**Клуб в интерфейсе есть с 17.10.2026** — одной страницей управления, а не подстраницами выше: турниры клуба по стадиям, данные клуба и состав (ADR-043). Подстраницы — когда появятся финансы клуба.

### 2.3. Консоль судьи

```
/console/:tournamentId               Главный экран проведения
/console/:tournamentId/players       Состав, снятия, «вне зачёта»
/console/:tournamentId/standings     Таблицы и текущие места
/console/:tournamentId/finish        Завершение и публикация
```

Сегодня всё это живёт на одном маршруте `/console/:tournamentId`. Разносить есть смысл только если экран перестанет помещаться, — не раньше.

### 2.4. Администрирование

```
/admin                               Сводка платформы
/admin/clubs                         Клубы и тарифы
/admin/players                       Игроки, объединение дублей
/admin/tournaments                   Все турниры
/admin/ratings                       Ручные корректировки с причиной
/admin/anomalies                     Флаги аномалий рейтинга
/admin/audit                         Журнал действий
```

Самая дальняя часть черновика. До первых живых клубов админка — это семь экранов, обслуживающих ноль записей.

## 3. Ключевые экраны — черновик

> **Капслок в схемах ниже — условность наброска, а не требование.** Заголовки капслоком в интерфейсе запрещены (`07-design-system.md`, запрет №10): на казахском они читаются хуже всего.

### 3.1. Страница турнира, публичная

```
┌──────────────────────────────────────────┐
│ ← Турниры                                │
│                                          │
│ ВЕЧЕРНИЙ ТУРНИР 450          ● идёт      │  Oswald 30, метка с наклоном 9°
│ КНТ Winners · Астана                     │  Inter 13, ink-500
│ 12 марта, 20:00 · взнос 3 000 ₸          │
│                                          │
│ [Обзор] [Участники 18] [Сетка] [Итоги]   │  активная вкладка — красная линейка
├──────────────────────────────────────────┤
│  Сейчас играют                           │
│  ┌────────────────────────────────────┐  │
│  │ Стол 1   Ма Л  724  ·  Копаев  211 │  │
│  │ Стол 3   Ким А  380  ·  Ли В   356 │  │
│  └────────────────────────────────────┘  │
│                                          │
│  Условия                                 │
│  Рейтинг до 450 · Круговая в группах     │
│  4 группы по 5 · Из группы выходят 2     │
│                                          │
│  [   Записаться · 3 000 ₸   ]            │  primary, единственная на экране
└──────────────────────────────────────────┘
```

Правило: если турнир идёт — блок «Сейчас играют» первый, всё остальное ниже. Человек открывает страницу во время турнира именно за этим.

### 3.2. Сетка

**Мобильный:** свайп по раундам, один раунд на ширину экрана, точки-индикаторы снизу, липкий заголовок раунда. Стрелки связи не рисуются — вместо них подпись «победитель проходит в ¼ финала».

**Десктоп:** полная схема с горизонтальным скроллом и связями.

**Групповой этап на мобильном:** матрица со скроллом по горизонтали, первая колонка с фамилиями зафиксирована. Это одно из двух разрешённых мест с горизонтальным скроллом таблицы.

### 3.3. Рейтинг

```
┌──────────────────────────────────────────┐
│ РЕЙТИНГ                                  │
│ [Поиск игрока                       🔍]  │
│ [Город ▾][Клуб ▾][Пол ▾][+ Фильтр]       │
│ Найдено 1 248                            │
├──────────────────────────────────────────┤
│  #   Игрок                Клуб    Рейтинг│
│ ───────────────────────────────────────  │
│   1  ● Ма Лэй             Nomad     724↑2│
│   2  ● Иванов Пётр        Winners   688↓5│
│   3  ● Ким Александр      Sana      651 —│
└──────────────────────────────────────────┘
```

На мобильном строка превращается в карточку: место и рейтинг крупно, остальное подписью. Спарклайн динамики — только от 640px. Сортировка и пагинация серверные обе сразу (`07-design-system.md`, 6.1).

### 3.4. Профиль игрока

Верх экрана — рейтинг числом в Oswald 44 и дельта за месяц. Ниже кривая за выбранный период. Ниже — статистика, последние матчи, турниры. Личные встречи с конкретным соперником — отдельный экран, попадание с любой строки истории.

Кривая рейтинга уже написана своим SVG. Заменять её на графическую библиотеку имеет смысл только ради зума и тултипов по тапу, и это отдельное решение с замером веса.

### 3.5. Создание турнира

Мастер из трёх шагов, а не одна длинная форма. Формулировки — на языке зала.

```
Шаг 1. Когда и где
  Название · Дата и время · Клуб · Сколько столов

Шаг 2. Кто играет
  Взнос · Ограничение по рейтингу · Возраст · Пол · Лимит мест

Шаг 3. Как играем
  Сколько человек ждёте?  [до 12] [12–24] [24–48] [больше]
  Сколько времени есть?   [2 часа] [3 часа] [весь день]
  → Система предлагает формат словами:
    «Четыре группы по шесть, из группы выходят двое,
     дальше олимпийка. Примерно 3 часа на 6 столах.»
  [Подходит]  [Выбрать формат вручную]
```

Прямое следствие принципа 1.1: организатор отвечает на понятные вопросы, редактор схемы видит только если сам захочет. Предпросчёт даёт движок `brackets` (ADR-024), а не отдельная формула в интерфейсе, — иначе обещание на экране разойдётся с тем, что построит сервер.

Обязательная кнопка на списке турниров: **«Повторить прошлый»** — копирует настройки, спрашивает только дату. Организатор проводит турнир восемь раз в месяц, и это разница между «пользуюсь» и «забросил».

## 4. Консоль судьи

Самый важный экран продукта. Проектируется отдельно от остального приложения. **Не черновик:** требования идут из ТЗ и из списка приоритетов брифа.

### 4.1. Условия эксплуатации

Судья стоит, держит телефон одной рукой, в зале шумно, свет неровный, руки могут быть влажными. Действие повторяется 50–80 раз за вечер. Wi-Fi может отсутствовать полностью.

### 4.2. Требования

- Минимальная зона нажатия **56×56px**, у кнопок счёта — 64px
- Основные действия в нижней трети экрана, доступной большим пальцем
- Контраст текста — 7:1, набор токенов `--night-*` (`07-design-system.md`, 3.3). Единственное исключение — белый текст на заливке `--red-600`, там 5.83:1
- Никаких наведений и контекстных меню по долгому нажатию
- Подтверждение только для необратимого: отмена матча, завершение турнира
- Тёмная тема по умолчанию — в зале приглушённый свет
- Отклик кнопки ввода счёта — **менее 50 мс локально, без сети** (ТС 8.1)

### 4.3. Главный экран

```
┌──────────────────────────────────────────┐
│ ВЕЧЕРНИЙ 450        ⟳ 3 в очереди   ●●●  │  индикатор синхронизации
├──────────────────────────────────────────┤
│ СТОЛЫ                                    │
│ ┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐    │
│ │ 1  ││ 2  ││ 3  ││ 4  ││ 5  ││ 6  │    │
│ │идёт││своб││идёт││идёт││своб││идёт│    │
│ └────┘└────┘└────┘└────┘└────┘└────┘    │
├──────────────────────────────────────────┤
│ ИГРАЕТСЯ                                 │
│ ┌──────────────────────────────────────┐ │
│ │ Стол 1 · гр. 1                       │ │
│ │ Ма Л              724                │ │
│ │ Копаев В          211                │ │
│ │           [ Ввести счёт ]            │ │
│ └──────────────────────────────────────┘ │
├──────────────────────────────────────────┤
│ В ОЧЕРЕДИ                          ждут 7│
│ гр.2  Ким А : Ли В        [На стол 2 ▸]  │
│ гр.1  Абай С : Ержан Т    [На стол 5 ▸]  │
└──────────────────────────────────────────┘
```

Состояние стола передаётся словом и цветом одновременно: «идёт» / «своб». Одним цветом — нельзя (запрет №6).

### 4.4. Ввод счёта — критический компонент

Требование ТЗ: закрытие встречи **не более чем в два действия**.

```
┌──────────────────────────────────────────┐
│ ×                              Стол 1    │
│                                          │
│ Ма Лэй                     724           │  Oswald 30
│ Копаев Валентин            211           │
│                                          │
│ ─────────────────────────────────────    │
│                                          │
│   ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐   │
│   │ 3:0  │ │ 3:1  │ │ 3:2  │ │ W:L  │   │  64px, --red-600
│   └──────┘ └──────┘ └──────┘ └──────┘   │
│   ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐   │
│   │ 0:3  │ │ 1:3  │ │ 2:3  │ │ L:W  │   │  64px, обводка
│   └──────┘ └──────┘ └──────┘ └──────┘   │
│                                          │
│   Последняя игра у обоих                 │  контекстная подсказка
│                                          │
│   [ Ввести по сетам ]   [ Отменить игру ]│
└──────────────────────────────────────────┘
```

Одно нажатие на кнопку счёта — встреча закрыта, лист уходит, стол освобождается, таблица пересчитана. **Никаких «Сохранить».** Запись идёт в локальную базу, отправка на сервер — фоном, через очередь.

Ввод по сетам — вторичный путь за кнопкой. Он нужен редко.

**Контекстные подсказки** выводятся над панелью, когда применимы:

- «Последняя игра у обоих» — после встречи оба свободны
- «Ждёт дольше всех» — приоритет назначения
- «Решающая за выход из группы»

Верхний ряд кнопок — заливка `--red-600`, и он лежит на приподнятой карточке `--night-raised`. Заливка к этой поверхности даёт 2.93:1, поэтому кнопки получают границу 1px `--night-red` (`07-design-system.md`, 3.3).

## 5. Экран зала

Отдельный маршрут `/screen/:publicToken`, открывается на телевизоре без авторизации. Тёмный фон, крупный набор, ничего интерактивного. Показывает столы с текущими встречами, очередь ближайших и групповые таблицы по ротации.

**Обновление — потоком SSE**, `GET /api/v1/public/screen/:publicToken/stream`. Вебсокета здесь нет и не будет: поток односторонний, экран зала ничего не отправляет. Вариант `WS /ws/screen/:publicToken` рассмотрен и отклонён — **ADR-025**. Любой макет или спецификация, где написано «обновление по WebSocket», противоречит принятому решению.
