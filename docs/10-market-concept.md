# 10. Раздел «Маркет» — каталог, магазины, заказы

_Согласовано с владельцем продукта 19.10.2026. Решение — ADR-058. Код пишется по этому документу частями, каждая — с планом файлов и миграций по брифу 2.1._

_Форум, обсуждения, текстовые отзывы и «Купля-продажа б/у» сюда не входят — они придут вместе с форумом._

---

## 1. Зачем раздел

**Как KTTF зарабатывает на магазинах.** Та же модель, что у клубов (ADR-055): KTTF приводит игроков, сайт сводит их с магазином — «Заказать» открывает мессенджер магазина с готовым текстом. Оплата идёт магазину напрямую. Магазин видит в кабинете, кто пришёл через KTTF, откуда и когда, и за это потом платит: продвижение товара, место в «Где купить», реклама.

**Маркет — ещё и справочник инвентаря продукта.** Игрок выбирает основание и накладки из каталога, клуб — столы. Отсюда «Выбор игроков», «Кто играет», «Где стоит» и популярность — как у RTTF, но на нашем рейтинге.

**Что есть у RTTF и где он слаб.** Разбор — раздел 8. Коротко:

- С 2024 года у RTTF **нет цен магазинов**. Блок «Где купить» убран, на его месте — партнёрские виджеты Яндекс.Маркета. Каталог стал справочником характеристик
- Магазинов семь, товары есть у трёх. RTTF сам разбирает сайты магазинов и вручную связывает ссылки с товарами — отсюда кроссовки на странице накладки
- Сильная сторона — социальный слой: «Играю», «Выбор игроков», «Кто играет» с рейтингом

**Чем мы сильнее:**

1. **Цены в ₸ и наличие** у предложений магазинов, с отметкой «обновлено N дней назад». Минимальная цена — на карточке
2. **Магазин ведёт свои предложения сам** в кабинете, без ручного разбора сайтов. Позже — фид в формате прайс-листа Kaspi: он уже есть у каждого магазина, торгующего на Kaspi
3. **«Кто чем играет» на нашем рейтинге:** «Чем играют игроки 400+», «Выбор игроков Казахстана»
4. **Магазин при клубе.** Клуб получает функционал магазина, страницы клуба и магазина ссылаются друг на друга
5. **Журнал переходов для магазина:** каждый заказ и переход — строкой с источником. У RTTF — `onclick` без ссылки и без отчёта магазину
6. **Варианты товара:** ручка, толщина губки, цвет, размер — магазин отмечает, что из них есть в наличии

**Рынок в РК** (раздел 9): профильных магазинов мало — ForTennis.kz (Алматы), ADD Table Tennis Shop при клубе ADD (Астана), ttdonic.kz. Значит, **главный источник предложений — клубы, торгующие инвентарём**, и два-три профильных магазина. Каталог полезен и без них: характеристики, кто играет, где стоит.

**Приоритет продукта не меняется:** турнир создаётся, проводится и выдаёт результаты. Маркет идёт короткими ветками и не трогает консоль.

### 3.3. V2

- **Фид цен в формате прайс-листа Kaspi** (XML: `offer sku` → модель, бренд, наличие, цена). Магазин даёт ссылку, мы забираем раз в час и сопоставляем SKU с товарами каталога — сопоставление подтверждает магазин
- **Заказ на сайте:** корзина в пределах одного магазина, имя и телефон покупателя, статусы в кабинете магазина. Требует уведомлений ТЗ 10, иначе заказ лежит непрочитанным. Хранится в РК — запрет №4
- **Оценки товара игроками** — баллы «скорость / вращение / контроль» без текста, с рейтингом оценившего. Своя шкала поверх шкал производителей
- Продвигаемое предложение в «Где купить» и в списке, с меткой «Реклама»
- Включение тарифов магазинов
- «Призы от магазина» — магазин-партнёр турнира

### 3.4. Вместе с форумом

- Текстовые отзывы о товарах
- «Купля-продажа б/у» — объявления, привязанные к товару каталога
- Обсуждение товара

### 3.5. Отсеяно

| Что                                        | Почему                                                                                                |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Разбор сайтов магазинов парсером           | Хрупко и ошибается в сопоставлении — так у RTTF и вышло. Магазин ведёт данные сам или отдаёт фид      |
| Приём оплаты KTTF                          | Решение владельца: магазины принимают оплату сами. У Kaspi и нет публичного API ссылки для посредника |

```prisma
  productId String
```

Поиск — расширение `pg_trgm` и индекс по `name`, бренду и `aliases`. `PENDING` видна только в магазине, который её предложил.

### 4.2. Справочник в профилях — M1.2

```prisma
// Player — три ссылки на товар рядом со строками ADR-035
bladeProductId          String?   // товар BLADE
rubberForehandProductId String?   // товар RUBBER
rubberBackhandProductId String?   // товар RUBBER

model ClubTable {
  clubId    String
  productId String
  count     Int
  @@id([clubId, productId])
}
```

Инвентарь — три ссылки в самой анкете, а не отдельная таблица: слотов ровно три, «кто играет» становится обычным условием списка игроков. Строки `Player.blade`, `rubberForehand`, `rubberBackhand` (ADR-035) остаются для того, чего нет в каталоге. Администратор видит несопоставленные строки и связывает их с товарами — так строки становятся справочником, как и задумывал ADR-035. `Club.tableBrand` остаётся до переноса и потом не показывается.

### 4.3. Характеристики — `Json` со схемой в общем коде

`attrs` проверяется описанием своей категории — `PRODUCT_ATTRIBUTES` в `kttf-shared`. Это одна правда для формы, сервера, фильтров и импорта. Каждая характеристика — ключ, подпись, тип (перечисление, несколько из перечисления, число, диапазон чисел, да/нет), единица, «фильтруется ли». Значения — из перечислений, а не свободным текстом: у RTTF «OFF-» не совпадает ни с одним значением фильтра, и такой товар фильтр не находит.

| Категория       | Характеристики RTTF, которые повторяем                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Основания       | Тип основания, количество слоёв, конструкция (с композитом / без), вес, толщина, скорость, контроль, вибрация, размер лопасти, стиль игры, игровое пятно, форма ручки |
| Накладки        | Тип накладки, тензор, скорость, вращение, контроль, цвет, толщина губки, жёсткость губки словом и в градусах, цвет губки, стиль игры                                  |
| Мячи            | Материал, звёзды, конструкция (со швом / без), упаковка, количество мячей, цвет                                                                                       |
| Столы           | Тип (для помещений / всепогодный / мини), конструкция (складной / нет), материал, толщина столешницы, вес, размер упаковки, цвет                                      |
| Обувь           | Тип (кроссовки / шлёпанцы / стельки), цвет                                                                                                                            |
| Футболки, шорты | Тип, для кого, цвет, размер, материал                                                                                                                                 |
| Чехлы           | Тип (одинарный, двойной, кейс, по форме ракетки, тубус), материал, цвет                                                                                               |
| Носки           | Вид (короткие / длинные), цвет                                                                                                                                        |

Точный список ключей и значений собирается по выгрузке RTTF (раздел 6): что встречается у них, то и становится перечислением, опечатки сводятся к одному значению. Числа производителей показываются с пометкой «шкала производителя — сравнивайте внутри одной фирмы». Фильтры — индекс GIN по `attrs`; при каталоге в тысячи товаров отдельный поисковый движок не нужен.

### 4.4. Магазин — M1.3


## 6. Наполнение каталога

**Решение владельца — повторить каталог RTTF**: позиции, характеристики, фото и описания.

**Как:**

1. **Выгрузка.** Скрипт `kttf-shots/scripts/rttf-crawl.py` обходит карточки `rttf.ru/items/{id}` по порядку номеров — `robots.txt` RTTF их не закрывает. Номера идут до ~8300. RTTF закрывает адрес после нескольких быстрых запросов, поэтому один запрос в 7 секунд и долгое ожидание после отказа. Сырой HTML хранится на машине разработчика, в репозитории его нет
2. **Разбор.** `rttf-parse.py` → JSON Lines: категория, производитель, название, характеристики «метка — значение», описание, фото с размерами, игроки RTTF (только для оценки популярности — к нашим игрокам не привязываются)
3. **Сведение.** Метки и значения RTTF сводятся к ключам и перечислениям `PRODUCT_ATTRIBUTES`; опечатки и варианты написания — к одному значению. Отчёт о несведённом — до импорта
4. **Импорт.** Администрирование → «Импорт». Фото скачивает сервер и прогоняет через `sharp` (раздел 6 `docs/09`), у фото `credit = rttf.ru`. `rttfId` позволяет повторить импорт и обновить карточки
5. **Русские написания** (`aliases`) — из строк инвентаря наших игроков (ADR-035) и вручную для ходовых моделей

Демо-данные для localhost — тот же импорт на части выгрузки.

## 8. Маркет RTTF — что изучено

Источники: страницы rttf.ru и снимки Wayback Machine 2020–2026.

- **Разделы:** `/market/`, категории `/items/?cat=N` (накладки 1, основания 2, футболки 4, шорты 5, мячи 6, обувь 8, чехлы 10, столы 11, носки 15), товар `/items/{id}`, магазины `/stores/`, магазин `/stores/{id}`, производители `/firms/`, «Кто играет» `/players/inventory?blades[]=…`, «Информация для магазинов» `/feedback/3`, б/у `/sellings/`, прайс рекламы `/content/16`

- **Магазины:** логотип, «интернет-магазин», «есть оффлайн», сайт, телефон, «Представитель на сайте», описание, число товаров по категориям. Семь магазинов, товары у трёх

## 10. Риски

### 10.1. Пустой маркет

Профильных магазинов мало. Против: каталог полезен и без цен (характеристики, кто играет, где стоит), магазины при клубах — главный источник предложений, первые 2–3 магазина администратор заводит и наполняет вместе с ними.

### 10.2. Устаревшие цены

Цена, которой уже нет, хуже отсутствия цены. Против: свежесть у каждого предложения, автоматический уход из «от N ₸» через 90 дней, одна кнопка «Цены актуальны», в V2 — фид.

### 10.3. Дубли и мусор в каталоге

Против: перечисления вместо свободного текста, подсказки похожих позиций при вводе, предложенные карточки — на проверке до общего каталога, слияние дублей с переносом предложений.

### 10.4. Права на данные RTTF

Каталог RTTF как база данных охраняется правом её изготовителя на извлечение существенной части (ГК РФ, ст. 1334), фото и тексты описаний — авторским правом в России и в Казахстане. Владелец принял решение повторить каталог, зная это. Что снижает риск: у каждого фото хранится `credit`, у товара — `rttfId`, поэтому фото и описания RTTF находятся одним запросом и заменяются — на фото магазинов по мере их подключения или на свои. Снятие по жалобе правообладателя — вручную в администрировании.

### 10.5. Персональные данные — запрет №4

Журнал хранит, кто из вошедших нажал «Заказать», — это персональные данные; они в Postgres в РК. Магазину показывается только «вошедший / гость». IP не хранится. Контакт покупателя к нам не попадает: он пишет магазину сам. Заказ на сайте (V2) хранит имя и телефон в РК.

### 10.6. Конфликт интересов

KTTF продаёт магазину продвижение и показывает «Где купить». Порядок предложений по умолчанию — город и цена, оплаченное место всегда с меткой «Реклама».
